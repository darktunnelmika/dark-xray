# DARK XRAY 🖤

**پنل مستقل مدیریت Xray با رابط فارسی سایبری، نمایندگی و کنترل دسترسی.**

نسخه: `0.6.0-standalone-lab` · وضعیت: **آزمایشی / تک‌سرور**

> [!WARNING]
> این نسخه برای سرور آزمایشی جداست، نه جایگزینی فوری پنل مشتری‌دار. اتصال به Xray واقعی، اعمال قانون فایروال روی بسته‌ها، نصب روی VPS تازه و عملکرد زیر بار هنوز تأیید نشده‌اند. تست خودکار با شبیه‌ساز هسته، جای این آزمایش‌ها را نمی‌گیرد.

## مستقل از هر پنل دیگر

برای نصب و اجرا به **سنایی، توکن سنایی، ورود دوم یا صفحات پنل دیگری نیاز نیست**. رابط، API، دیتابیس، احراز هویت و کنترل هسته در همین پروژه قرار دارند. Xray-core موتور جداگانهٔ اتصال است و باینری آن داخل مخزن نیست.

```text
DARK UI → DARK API / Access Control → DARK Database → Xray-core
                                              └→ IP guard (nftables)
```

## امکانات موجود در کد

| بخش | توضیح |
|---|---|
| رابط | فارسی، راست‌به‌چپ، تم سایبری دارک و فرم‌های اینباند، هاست، اوتباند و روتینگ |
| مشتری | مالک مشخص، حجم، انقضا، چند اینباند، سقف IP و تنظیم HWID |
| نمایندگی | اینباندهای مشترک، سقف تعداد مشتری، سهمیه، قطع دستی و کنترل دسترسی سمت سرور |
| مصرف | دفتر مستقل؛ حذف یا ریست مشتری مصرف تاریخی نماینده را پس نمی‌دهد |
| هسته | کنترل مستقیم فرایند Xray، اعتبارسنجی تنظیمات و تلاش برای برگشت از اجرای ناموفق |
| IP | سیاست یکپارچه، حالت مشاهده/اعمال، کارگر محدود nftables، گزارش و رفع مسدودی |
| امنیت | رمز هش‌شده، نشست، TOTP، کلید API با مجوز و ابطال |
| نگهداری | نصاب اولیه، systemd، ابزار دامنه/گواهی و بکاپ رمزدار |

**محدودیت IP، شمارش قطعی دستگاه یا انسان نیست.** چند دستگاه پشت NAT ممکن است یک سهم بگیرند. روی تانل یا CDN، تا IP واقعی در نقطهٔ فایروال تأیید نشده حالت اعمال را فعال نکن. محدودیت مشترک چندنودی در این نسخه وجود ندارد.

## شروع نصب آزمایشی

از صفحهٔ مخزن `Code → Download ZIP` را انتخاب کن، آرشیو را استخراج کن و وارد پوشه‌ای شو که `setup.sh` داخل آن است. سپس روی VPS آزمایشی:

```bash
sudo bash setup.sh \
  --public-address YOUR_SERVER_IP \
  --ssh-port YOUR_ACTUAL_SSH_PORT \
  --install-os-packages
```

**مقادیر نمونه را جایگزین کن.** نصاب رمز را تعاملی می‌پرسد و رمز پیش‌فرض ندارد. دسترسی اولیه روی loopback است؛ برای ورود، SSH forwarding و سپس HTTPS طبق راهنما تنظیم می‌شود. نصاب پورت‌های داده را خودکار باز نمی‌کند. بخش IP نیازمند تأیید جداگانهٔ مدیر سیستم است.

## وضعیت توسعه

این نسخه معادل کامل سنایی نیست. چندنود، محدودیت IP سراسری چندنود، بعضی پروتکل‌ها و فرم‌های پیشرفته، سازگاری آماده با میرزا، مهاجرت و ارتقای خودکار هنوز کامل نشده‌اند. هیچ نشان «تست موفق» در این README به آزمایش شبکهٔ واقعی اشاره نمی‌کند.

گزارش `qa/summary.json` متعلق به ساخت قبلی نسخهٔ ۰.۶ است. نتیجهٔ بررسی همین بسته در `qa/repository-preflight.json` جداگانه ثبت می‌شود. GitHub Actions بعد از بارگذاری اجرا خواهد شد و نتیجهٔ آن از قبل فرض نشده است.

## توسعه و تست

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python tools/repo-check.py
bash tests/run-tests.sh
```

برای تست JavaScript به Node.js نیاز است. تست‌های پیش‌فرض از هستهٔ ساختگی و اجرای آزمایشی فایروال استفاده می‌کنند؛ تست واقعی Xray جداگانه و اختیاری است. آزمون مرورگر نیز بخشی از ادعای موفقیت این بسته نیست.
