# DARK XRAY 🖤

پنل مستقل مدیریت Xray با رابط فارسی سایبری، مالکیت مشتری، مدیریت نمایندگان و کنترل سطح دسترسی.

نسخهٔ مبنا: `0.6.0-standalone-lab`

> [!CAUTION]
> **انتقال سورس هنوز کامل نیست؛ فعلاً از این مخزن نصب نکنید.**
> ۶۴ مسیر از ۶۷ فایل بستهٔ اصلی در مخزن حضور دارند. سه فایل زیر هنوز منتقل نشده‌اند و نبود ماژول‌های اجرایی مانع راه‌اندازی کامل برنامه است:
>
> - `backend/guard_bridge.py`
> - `backend/guardd.py`
> - `backend/policy_api.py`

## وضعیت انتشار — ۱۳ سپتامبر ۲۰۲۶

فایل‌های پذیرفته‌شدهٔ نوبت قبل بازیابی شدند. رابط `web/`، ابزارهای `tools/`، تست‌های `tests/`، مستندات، فایل مجوز، گردش‌کار GitHub Actions، فایل‌های سرویس و این ماژول‌های بک‌اند منتقل شده‌اند:

`auth.py`، `backup.py`، `core.py`، `dark_policy.py`، `manager.py` و `server.py`.

همچنین `tests/test_v06.py` که در انتقال قبلی جا مانده بود اضافه شد و اختلاف انتقال `tests/legacy/test_policy.py` و قالب‌بندی سه گزارش QA با نسخهٔ اصلی اصلاح شد. محتوای فایل‌های برنامه نسبت به بستهٔ اصلی تغییر داده نشده است.

**ارسال سه فایل باقی‌مانده در ابزار انتشار با پیام «وضعیت ایمنی درخواست قابل تعیین نبود» متوقف شد.** این وضعیت با نداشتن دسترسی نوشتن گیت‌هاب متفاوت است. هیچ فایل جایگزین ناقص یا ادعای تکمیل برای پوشاندن این مشکل اضافه نشده است.

برای فهرست دقیق، تعداد فایل‌ها و هش‌های تطبیق، [PUBLISH-STATUS.json](PUBLISH-STATUS.json) را بخوانید. راهنماهای داخل مخزن توصیف بستهٔ توسعه‌ای کامل هستند و تا رفع کمبود فایل‌ها نباید دستورهای نصب آن‌ها را اجرا کرد.

## معماری مستقل

```text
DARK UI → DARK API / Access Control → DARK Database → Xray-core
                                              └→ IP guard (nftables)
```

سنایی یا پنل دیگری پیش‌نیاز این پروژه نیست. رابط، حساب‌ها، دیتابیس و API متعلق به DARK هستند و Xray-core موتور مستقل اتصال است. ویژگی‌های بستهٔ توسعه‌ای شامل مدیریت نماینده، مشتری روی اینباند مشترک، دفتر مستقل مصرف، محدودیت IP، ورود و TOTP، نصب اولیه و بکاپ رمزدار است. **حضور این سورس‌ها به معنی آمادگی بهره‌برداری نیست.**

## آزمون‌ها و محدودیت‌ها

فایل‌های `qa/` گزارش‌های تاریخی توسعهٔ نسخهٔ ۰.۶ هستند، نه نتیجهٔ اجرای تازهٔ این شاخه. نتیجهٔ قدیمی ۱۸۹ آزمون را نباید موفقیت CI فعلی دانست. اولین اجرای Actions روی کامیت بازیابی `8316f19` در مرحلهٔ Repository hygiene ناموفق شد؛ آزمون‌های بعدی آن اجرا نشدند. نتیجهٔ اجراهای بعدی در تب Actions قابل مشاهده است و موفقیت آن‌ها در این متن ادعا نمی‌شود.

اتصال با Xray واقعی، اثر فایروال روی بسته‌های واقعی، نصب روی VPS تازه، صدور گواهی زنده و عملکرد زیر بار هنوز تأیید نشده‌اند. چندنود، IP سراسری چندنودی، مهاجرت و بعضی امکانات پیشرفته هم ناتمام‌اند.
