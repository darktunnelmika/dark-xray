# DARK SWAP: پورت مستقل برای مقصد مشترک

این قابلیت TCP را بدون بازکردن احراز هویت از یک پورت جدا در واسط، به اینباند نود مقصد منتقل می‌کند. مشترک‌بودن اینباند به معنی مشترک‌بودن پورت ورودی SWAP نیست. نمونه:

| مسیر | شنونده واسط | مقصد |
| --- | --- | --- |
| مسیر قبلی هلند | هلند:6800 | همان سرویس قبلی هلند |
| SWAP آلمان | هلند:6801 | شنونده تونلی آلمان:6802 |
| Direct آلمان | بدون واسط | پورت اصلی همان اینباند روی آلمان |

## مراحل در پنل

1. اینباندها ← ویرایش اینباند مشترک ← عمومی ← مقصدهای استقرار؛ آلمان را انتخاب و ذخیره کنید. پروتکل مشتری و انتقال باید از TCP استفاده کند.
2. در کارت آلمان، بخش DARK SWAP ← تنظیمات، یا از صفحه اختصاصی DARK SWAP ← مسیر جدید.
3. واسط هلند، پورت آزاد 6801، همان اینباند مشترک، مقصد آلمان، شنونده مقصد 6802 و نام دلخواه مسیر را وارد کنید. اگر آلمان از قبل Tunnel Port دارد، همان پورت به‌صورت ثابت استفاده می‌شود.
4. آدرس ورودی ایران و پورت خارجی آن را وارد کنید؛ این دو مقدار آدرس لینک ساب هستند. پورت ورودی ایران می‌تواند با پورت هلند متفاوت باشد.
5. مسیر را ذخیره کنید؛ خاموش است. تونل ایران را بیرون از این قابلیت طوری تنظیم کنید که ورودی ایران را به هلند:6801 برساند. دسترسی شبکه/فایروال از هلند به شنونده آلمان هم لازم است.
6. تیک DARK SWAP را در کارت آلمان فعال کنید، یا در صفحه اختصاصی فعال‌سازی را بزنید. تغییر تیک همان لحظه مستقل از دکمه ذخیره اینباند اعمال می‌شود. ابتدا مقصد باید تنظیمات شنونده را تأیید کند، سپس واسط تأیید می‌شود.
7. ساب مشتری را به‌روز کنید. لینک جدا با نام مسیر و DARK SWAP افزوده می‌شود؛ Direct آلمان و مسیرهای قبلی حذف نمی‌شوند. Host تکراری دستی نسازید.
8. برای تغییر یا حذف مسیر، ابتدا خاموش‌کردن و تأیید آن را کامل کنید. حذف/تعویض مقصد به تأیید پاک‌سازی شنونده آماده‌شده نیاز دارد. شنونده تونلی اصلی مقصد حذف نمی‌شود.

## رفتار و محدودیت‌ها

- مصرف و اعتبار مشتری تنها در نود مقصد ثبت می‌شود؛ واسط مشتری یا سهمیه جدید نمی‌سازد. احراز هویت و سیاست خروجی همان اینباند مقصد، از جمله WARP یا قوانین روتینگ مقصد، اعمال می‌شود.
- مقصد از شنونده تونلی استفاده می‌کند تا IP واسط به‌عنوان IP واقعی مشتری وارد کنترل IP نشود. Direct مقصد همچنان رفتار مستقل خود را دارد.
- خرابی مقصد به خروج اینترنت واسط برنمی‌گردد. انتشار لینک نیازمند سلامت و تأیید تنظیمات هر دو نود است؛ این بررسی سلامت، اثبات اتصال سرتاسری نیست.
- عیب‌یابی پنل آمادگی شنونده واسط و اینترنت مقصد را جدا بررسی می‌کند. برای تأیید تونل ایران و کل مسیر، خود لینک مشتری را در برنامه اتصال تست کنید.
- اعمال شنونده در موتور فعلی ممکن است با بارگذاری مجدد تنظیمات، اتصال‌های موجود نود را دوباره برقرار کند؛ جداسازی پورت به معنی تضمین بدون قطع‌شدن نشست نیست.
- انتقال‌های TCP/RAW، gRPC، WS، HTTP Upgrade و XHTTP قابل تعریف‌اند. UDP/mKCP در این مدل پشتیبانی نمی‌شود. دامنه و گواهی/REALITY همان اینباند مقصد حفظ می‌شود.
- قرارداد Agent همان schema 1 است؛ برای این قابلیت ارتقای مستقل Agent لازم نیست. مسیرها در نصب خودکار فعال نمی‌شوند.
- مدل قدیمی انتخاب خروجی برای کل اینباند خودکار به این مدل تبدیل نمی‌شود؛ مالک باید آن مسیرها را جدا خاموش/حذف کند.

## اعتبارسنجی

آزمون‌های واحد پوشش می‌دهند: اینباند مشترک روی واسط و مقصد، حفاظت پورت‌های Direct/تانل/مدیریت، ترتیب ACK، بازیابی بعد از عدم دریافت تأیید، دسترسی فقط مالک، حفظ Direct و حذف پاک‌سازی‌شده.

تست واقعی، دو Agent با HTTPS و Xray رسمی، لینک تولیدشده ساب را روی VLESS/REALITY با gRPC و TCP Vision مصرف می‌کند. انتقال TCP، محاسبه مصرف فقط روی مقصد، استقلال Direct هر دو نود، توقف مقصد بدون خروج جایگزین و اعمال غیرفعال‌سازی مشتری بررسی می‌شود. این محیط موقت، کیفیت WAN یا تونل واقعی ایران را تأیید نمی‌کند.
