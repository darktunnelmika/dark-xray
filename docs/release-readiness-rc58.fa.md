# آمادگی نصب و بازیابی DARK XRAY rc58

در ۴ اکتبر ۲۰۲۶، بستهٔ `0.10.0-rc58` از کامیت
`a7060e2b46cc52baf38510fffce8194d1e4d871d` بررسی شد. این گزارش مربوط به همین
بسته است؛ تغییر نسخه یا فایل‌های اجرایی به آزمون دوباره نیاز دارد.

## نتیجهٔ آزمون‌ها

| مسیر | نتیجه |
| --- | --- |
| ۱۱۱ تست نصب، بکاپ، بازیابی و آپدیت | پاس |
| دو ساخت مستقل tar.gz و zip | هش‌های یکسان |
| بررسی داخلی بسته | ۴۸۷ فایل منبع تأیید شد |
| نصب تمیز هاب و نود | پاس؛ شناسهٔ نصب با کامیت بسته برابر بود |
| Pair Code و TLS نود | پاس؛ کد مصرف شد و اتصال با بررسی گواهی برقرار شد |
| ارسال تنظیمات و عبور ترافیک واقعی VLESS | پاس |
| Production Gate روی هاب تازه | پاس، ۱۴٫۶۱۷ ثانیه |
| آپدیت موفق از همان بسته | پاس |
| خرابی عمدی پس از راه‌اندازی نسخهٔ جدید | برگشت خودکار کد و دیتابیس پاس شد |
| وضعیت سرویس‌ها پس از برگشت | فعال؛ دیتابیس `quick_check=ok` |
| بازیابی بکاپ واقعی هاب در پوشهٔ موقت | پاس؛ نسخهٔ بازیابی‌شده فعال نشد |

محیط نصب دو کانتینر Ubuntu 24.04 با systemd واقعی، Python 3.12 و Xray
26.3.27 بود. شبکهٔ این دو با یک اتصال خصوصی به هم وصل شد و namespace شبکهٔ
میزبان به اشتراک گذاشته نشد. گواهی آزمایشی فقط در کانتینرها مورد اعتماد بود.
این آزمون، صدور گواهی عمومی یا کیفیت WAN و تونل‌های تولید را نمی‌سنجد.

خرابی آپدیت پس از راه‌اندازی واقعی سرویس تزریق شد. آزمون هم بازگشت فایل قبلی
و مقدار قبلیِ یک رکورد را بررسی کرد و هم حذف جدول آزمایشیِ ساخته‌شده توسط نسخهٔ
ناموفق را. شناسهٔ نصب حفظ شد و مسیر پنل و فایل‌های رابط دوباره سالم پاسخ دادند.

در بازیابی بکاپ واقعی، ۸۱ جدول تجاری از مجموع ۸۶ جدول بدون تغییر ماندند؛ شامل
۵۱۷ کاربر Restore، ۲۰ محصول و ۲۲ سفارشِ موجود در لحظهٔ بکاپ. تغییرهای عمدیِ
بازیابی محدود به نشست‌ها، اعتبارنامه و وضعیت ربات، آمادگی دامنهٔ Restore و
مسیر فایل‌های TLS بود. کلید اصلی حفظ شد؛ توکن‌های ربات در نسخهٔ بازیابی‌شده
پاک شدند و اتصال مجدد به Forum لازم است. هاب اصلی تغییر نکرد و فایل‌های
موقتِ حاوی داده و بکاپ حذف شدند.

محیط آزمایشی در ابتدا `/tmp` بسیار کوچکی روی tmpfs داشت. آپدیتر پیش از
دست‌زدن به سرویس، کمبود فضا را تشخیص داد و درخواست را رد کرد. پس از استفاده
از `/tmp` روی دیسکِ همان کانتینر، آپدیت و برگشت کامل پاس شدند. این محدودیت
محیط بود و اصلاح کد لازم نشد.

شواهد عمومی: [`qa/release-readiness-rc58.json`](../qa/release-readiness-rc58.json).
اطلاعات خصوصی، کلیدها، توکن‌ها و بکاپ مشتریان داخل مخزن قرار نگرفته‌اند.

## راهنمای نصب نسخهٔ آزموده‌شده

روی یک VPS تمیز Ubuntu 24.04، ابتدا فایل نصب را دریافت کن، سپس همان کامیت
آزموده‌شده را نصب کن. نصب هاب و نود باید روی میزبان‌های جدا انجام شود.

```sh
curl -fsSL https://raw.githubusercontent.com/darktunnelmika/dark-xray/a7060e2b46cc52baf38510fffce8194d1e4d871d/install-online.sh -o dark-install.sh
sudo env DARK_XRAY_REF=a7060e2b46cc52baf38510fffce8194d1e4d871d bash dark-install.sh
sudo darkxray doctor
```

نصب‌کننده رمز مالک، پورت SSH و تنظیمات پنل را می‌پرسد. برای دامنه و HTTPS از
مسیر موجود نصب‌کننده یا `sudo darkxray domain --help` استفاده کن. این آزمون
از مسیر `release-install.py fresh` و provisioning واقعی، با وابستگی‌های آفلاین
استفاده کرد؛ مسیر دریافت آنلاین بسته‌ها و ACME عمومی جزو این پذیرش نیست.

برای نود، روی VPS جدا با دامنه‌ای که DNS آن درست تنظیم شده:

```sh
curl -fsSL https://raw.githubusercontent.com/darktunnelmika/dark-xray/a7060e2b46cc52baf38510fffce8194d1e4d871d/install-node.sh -o dark-node-install.sh
sudo env DARK_XRAY_REF=a7060e2b46cc52baf38510fffce8194d1e4d871d bash dark-node-install.sh
```

Pair Code را در بخش نودهای هاب وارد کن، مقصدهای اینباند را انتخاب کن و وضعیت
ارسال تنظیمات و سلامت نود را بررسی کن. Pair Code را مانند اعتبارنامهٔ خصوصی
نگه دار.

## بکاپ و بازیابی

بکاپ کامل را از بخش بکاپ پنل یا این دستورات بساز و بررسی کن. رمز در ترمینال
به‌صورت تعاملی پرسیده می‌شود و نباید داخل فرمان قرار گیرد.

```sh
sudo darkxray backup --output /root/dark-full.darkbackup
sudo darkxray backup-verify --archive /root/dark-full.darkbackup
sudo darkxray restore --archive /root/dark-full.darkbackup --destination /root/dark-recovered
```

مقصد بازیابی باید جدید باشد. دستور restore نسخهٔ بازیابی‌شده را فعال نمی‌کند.
پیش از فعال‌سازی روی میزبان جایگزین، تنظیمات شبکه و دامنه، TLS، توکن‌های جدید
ربات و اتصال مجدد Forum را تکمیل کن. داده‌های تجاری و کلید رمزگذاری حفظ
می‌شوند؛ نشست‌های قدیمی و آمادگی دامنه‌های میزبان قبلی معتبر فرض نمی‌شوند.
باینری Xray، تعریف سرویس‌های systemd و تنظیمات ACME میزبان باید جدا نصب شوند.

## آپدیت و برگشت

پیش از آپدیت یک بکاپ کامل بساز. مسیر موجود آپدیتر ابتدا منبع، وابستگی‌ها،
سلامت دیتابیس و فضای آزاد را بررسی می‌کند، سپس نسخهٔ بازگشت کد و SQLite را
می‌سازد. بعد از آپدیت، مسیر پنل و فایل رابط باید سالم باشند؛ شکست این مرحله
برگشت خودکار را اجرا می‌کند.

```sh
sudo darkxray update --ref a7060e2b46cc52baf38510fffce8194d1e4d871d --non-interactive
sudo darkxray doctor
```

## وضعیت انتشار

این مرحلهٔ آمادگی نصب و بازیابی پاس شده است. نسخهٔ تولید همچنان rc58 است؛
برچسب Stable تازه منتشر نشده. پیش از نهایی‌کردن پذیرش ربات، نمایش کارت اتصال
و اسکن QR در تلگرام روی گوشی باید تأیید شود. صحت محتوای QR، مبلغ خرید و تمدید،
و زمان شروع از اولین اتصال در آزمون‌های جداگانه تأیید شده‌اند.
